# Golden set

The benchmark: English questions over the four jurisdictions' statutes, each with gold article references pinned to a corpus edition, a reference answer, and the record of how it was verified (`rag_eval.schema.GoldenItem`).

- `golden_v<N>.jsonl`: frozen versions, one item per line. A frozen file changes only through a new version, and the merge queue holds it until the human has reviewed every line.
- `drafts/`: candidate items before verification: `golden_v0.jsonl` (60 items) and `golden_v1.jsonl` (180: the same 60, unchanged, and 120 added in v1), with `NOTES.md` for the verifier: how the drafts were made, what the build already checks, and where a reading should look hardest.
- The dev (120) and test (60) split is not in the drafts. It is assigned when v1 is frozen, by `uv run python -m plumbline.corpus.split` (seeded and stratified by category, place and language; `NOTES.md` shows the result as it stands).
- `DATASET_CARD.md`: the card published with the dataset (fields, splits, licences, intended use, limitations). `uv run python -m plumbline.corpus.export data/golden/golden_v<N>.jsonl dist/golden-v<N>` builds the folder to publish from a frozen file: the card with its statistics, the file and its dev and test halves, the synthetic leases, the corpus manifest, the licences, the changelog and checksums. It refuses a draft, and it withholds the reviewer's quoted statute text for items that cite a source this repository does not redistribute (Dubai, Colombia).
- `CHANGELOG.md`: what each version added, changed or dropped, and why.
- `asof_cases.json`: point-in-time cases for the as-of filter, not golden items. Each names a Spanish article and a date, the BOE version that must be in force that day (norm and start date), a phrase of its wording that must appear, and phrases from the versions around it that must not. They cover the LAU's minimum term from 2009 to 2019, the agency-fee rule of 2023, and October 2026's three steps (RDL 26/2026 for one day, Congress's restoration, RDL 29/2026), an article added in October that must not exist in March, a version the BOE file leaves undated, and an LPH version that takes effect after its edition's date. `apps/api/tests/corpus/test_asof_cases.py` keeps every case true against the pinned files; a retriever's test can serve each case's date and check what comes back.

## Freezing a version

1. **Verify.** For every item, fill `verification` in the draft (the passage quoted from the official text, a second source, the date and who checked), correcting the item if it is wrong. A correction to a v0 item goes in both drafts; `make check` fails if they disagree. Do not hand-edit the lines: list what was checked in a JSONL file, one object per item (`id`, `second_source`, and optionally `quoted_text`, `notes`, `checked_by`, `checked_on`), and run `uv run python -m plumbline.corpus.verify drafts/golden_v1.jsonl RECORDS --checked-by "..."`. It checks every given quote against the pinned article as it stood on the item's date, takes the cited paragraph from the pinned text when no quote is given, refuses to overwrite a verification without `--replace`, and writes nothing unless every record is good (`--dry-run` only checks). An item that cites a fetch-only source (Dubai, Colombia) is checked against the fetched text, but its `quoted_text` is stored as the withheld marker, never a copy, and `make check` refuses anything else. An out-of-scope item cites no article, so its record must carry its own `quoted_text`.
2. **Freeze v0.** Copy the verified `drafts/golden_v0.jsonl` to `golden_v0.jsonl`, remove the draft, and move the changelog's "Unreleased" lines for it under a heading for the version and its date. Items keep `added_in` v0 and `split` unassigned.
3. **Freeze v1.** Run `uv run python -m plumbline.corpus.split data/golden/drafts/golden_v1.jsonl data/golden/golden_v1.jsonl --drop ID ...`, which splits every draft item, leaves out the dropped ones after the split (so no item changes side because another was dropped) and writes the file with every item in dev or test, then remove the draft and write the changelog entry. Items from v0 keep `added_in` v0.
4. **Check.** `make check` refuses a frozen file with an unverified item, an item from a later version, or (from v1) no split. The merge queue then holds the file until the human has read every line and approved that commit.
5. **Publish.** `uv run python -m plumbline.corpus.export data/golden/golden_v1.jsonl dist/golden-v1` builds the folder to upload; nothing is published by running it.

Validate any file with `uv run rag-eval validate <file>`; `make check` validates them all, and also checks that every gold reference's article exists in its pinned file, that every lease-check item agrees with its lease's expected findings, that a later draft keeps the items of an earlier one unchanged, and that a frozen file is finished: every item verified, none from a later version, and from v1 on every item in dev or test.
